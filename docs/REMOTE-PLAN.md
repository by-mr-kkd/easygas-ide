# รีโมทจากมือถือ (ออกพร้อม 1.0.0)

สถานะ: กำลังทำ (เริ่ม 8 ต.ค. 2026)

## เป้าหมาย

เปิด EasyGAS IDE ทิ้งไว้บนคอม แล้วใช้มือถือเปิดเบราว์เซอร์มาสั่ง AI ดูพรีวิว กดเผยแพร่ได้ **จากนอกบ้านด้วย**
ไม่ต้องลงแอปบนมือถือ ข้อมูลและ AI ยังอยู่บนคอมของผู้ใช้ทั้งหมด หน้าจอมือถือใช้ layout ที่ `IdeShell` มีอยู่แล้ว
(แผงเดียว + แถบล่าง แชต/พรีวิว/โค้ด)

## ฟรี กับ Pro

| | ฟรี | Pro |
|---|---|---|
| ทาง | ลิงก์นอกบ้าน (Cloudflare quick tunnel, ค่าเริ่มต้น) หรือ Wi-Fi เดียวกัน | ลิงก์นอกบ้าน |
| ได้ลิงก์ยังไง | สแกน QR หรือพิมพ์ลิงก์จากหน้าตั้งค่าบนคอมเอง ลิงก์ใช้ได้ตราบที่คอมเปิดอยู่ คอมรีสตาร์ต = ต้องสแกนใหม่ | ลิงก์เดียวตลอด `easygaside.tech/r/<ชื่อที่ตั้งเอง หรือรหัสสุ่ม>` |
| แอปบนมือถือ | — | `easygaside.tech/app` ติดตั้งลงหน้าจอโฮมได้ (PWA) |
| แจ้งเตือน AI เสร็จ / ถามกลับ / ทดสอบรันจริงเสร็จ | — | Web Push จากคอมของผู้ใช้เอง |
| PIN | ตั้งได้ ไม่บังคับ | บังคับ |

## สิ่งที่ห้ามเสีย

- เซิร์ฟเวอร์ Next ยังผูก `127.0.0.1` (`HOSTNAME`) เหมือนเดิม ส่วนที่รับจากข้างนอกคือ gateway แยกต่างหาก
- `middleware.ts` ยังกัน DNS rebinding และ CSRF เหมือนเดิม
- ความลับ (API key, token ของ clasp/Claude) ไม่ออกไปถึงมือถือ เหมือนที่ไม่ออกไปถึงหน้าเว็บบนคอม

## สถาปัตยกรรม

```
มือถือ ─HTTPS─▶ Cloudflare quick tunnel ─▶ gateway 127.0.0.1:<gw> ─▶ Next 127.0.0.1:<port>
มือถือ ─HTTP──▶ (Wi-Fi เดียวกัน) gateway 0.0.0.0:<gw> ─────────────▶ Next 127.0.0.1:<port>
```

gateway (`lib/remote/gateway.ts`) อยู่ในโปรเซสเดียวกับ Next เริ่มจาก `instrumentation.ts` ตอนเปิดแอปถ้าเปิดสวิตช์ไว้
หน้าของ gateway เอง (จับคู่, PIN, ถูกบล็อก) เป็น HTML เล็ก ๆ ที่ gateway เสิร์ฟเอง Next ไม่เคยเห็นคำขอที่ยังไม่ผ่านด่าน

1. **จับคู่:** คอมออกรหัสครั้งเดียว อายุ 5 นาที ใส่ใน QR `/__egs/pair?c=<รหัส>` มือถือสแกน → ได้คุกกี้ `egs_dev`
   (`<deviceId>.<token>` สุ่ม 32 ไบต์, HttpOnly, Secure บน HTTPS, อายุ 30 วัน) gateway เก็บแค่ hash ของ token ใน `remote.json`
2. **PIN:** ถ้าตั้งไว้ ถามตอนเริ่มใช้และหลังไม่ได้ใช้ 30 นาที เก็บเป็น scrypt hash ผิด 5 ครั้ง ล็อก 15 นาที + คอมแจ้งเตือน
   ลืม PIN ตั้งใหม่ได้ที่คอมเท่านั้น
3. **ส่งต่อ:** ลบ `x-forwarded-*` ที่มากับคำขอ เขียน `Host` เป็น loopback ตรวจ `Origin` ว่าตรงกับ origin ของ gateway
   ก่อนเขียนเป็น loopback (ให้ `middleware.ts` และ server actions ของ Next ผ่านตามปกติ) ใส่ `x-egs-remote: <ค่าลับของโปรเซส>`
   ให้ฝั่ง Next รู้ว่ามาจากมือถือ และแก้ `Location` ที่ชี้ loopback ให้เป็น path
4. **กันเรื่องที่ทำจากมือถือไม่ได้:** ตั้งค่ารีโมท (เปิด/ปิด, PIN, อุปกรณ์), ถอนการติดตั้ง, ติดตั้ง/ล็อกอิน AI
   ทำได้เฉพาะบนคอม (`assertLocalRequest()` ใน server action)

### ข้อจำกัดของ quick tunnel ที่ทดสอบแล้ว (8 ต.ค. กับ cloudflared 2026.10.0)

- เอกสาร Cloudflare เขียนว่าไม่รองรับ SSE แต่ทดลองจริง: **คำตอบของ POST ไหลทีละก้อนปกติ** (ทั้ง `text/event-stream`
  และชนิดอื่น) ส่วน **GET ถูกเก็บไว้ส่งทีเดียวตอนจบ** แชต AI และ "ตรวจแอป" เป็น POST จึงใช้ได้ ห้ามเปลี่ยนเป็น GET/EventSource
- ถ้าไม่มีข้อมูลไหลเกิน ~100 วินาที Cloudflare ตัด (524) → gateway ส่ง `: keepalive` ทุก 15 วินาทีใน stream ที่เป็น
  `text/event-stream` (ตัวอ่านใน `ChatPanel` ข้ามบรรทัดที่ไม่ขึ้นต้นด้วย `data:` อยู่แล้ว)
- รับคำขอค้างพร้อมกันได้ 200 ไม่รับประกัน uptime ลิงก์เปลี่ยนทุกครั้งที่เปิด tunnel ใหม่

### Pro: แอป EasyGAS บนมือถือ (`easygaside.tech/app`)

คุกกี้ผูกกับชื่อโดเมน และแอปที่ติดตั้งบน iPhone ไม่ใช้ที่เก็บข้อมูลร่วมกับ Safari จึงให้ **หน้าบนโดเมนเรา** เป็นตัวเก็บการจับคู่:

1. แอปบนคอมรายงานลิงก์ tunnel ล่าสุดไปที่ `premium-remote` (Supabase edge function) ทุกครั้งที่ได้ลิงก์ใหม่ ด้วยคีย์ Pro +
   รหัสเครื่อง เซิร์ฟเวอร์เก็บแค่ รหัส/ชื่อ → ลิงก์ ชื่อตั้งเองได้ (a-z 0-9 -, 3–24 ตัว, ไม่ซ้ำ, เปลี่ยนได้เดือนละครั้ง)
2. จับคู่: หน้า `/app` (หรือ QR = `easygaside.tech/r/<ชื่อ>#c=<รหัส 6 หลัก>`) หาลิงก์ล่าสุด แล้วเรียก
   `POST <tunnel>/__egs/api/pair` ข้ามโดเมน (CORS อนุญาตเฉพาะ easygaside.tech, เปิดเฉพาะเครื่องที่เป็น Pro) ได้ device token
   + VAPID public key ของคอม เก็บใน localStorage `egs-machines` ของหน้าแอป
3. เปิด: หน้าแอปพาไป `<tunnel>/__egs/resume?next=<path>#<token>` → gateway ออกคุกกี้ให้โดเมน tunnel นั้น → ถาม PIN
4. แจ้งเตือน: หน้าแอปลง service worker แยกต่อคอมแต่ละเครื่อง (`/app/m/<id>/`, เพราะแต่ละคอมใช้ VAPID key ของตัวเอง) แล้วส่ง
   subscription ไปที่ `POST <tunnel>/__egs/api/push` (Bearer token) คอมส่ง Web Push เอง (`lib/remote/webpush.ts`, RFC 8291/8292
   ไม่มี dependency) เมื่อเทิร์น AI / ทดสอบรันจริงที่เริ่มจากมือถือนั้นจบ (gateway ใส่ `x-egs-device`) ข้อความเข้ารหัสถึงมือถือ
   ทดสอบกับ push service จริงของ Mozilla แล้ว: ส่งถึงและถอดรหัสได้ (8 ต.ค.) ฝั่ง Google (FCM) ยังไม่ได้ลองด้วยมือถือจริง
5. iPhone: แจ้งเตือนได้เฉพาะเมื่อเพิ่มแอปลงหน้าจอโฮม (iOS 16.4+) และต้องจับคู่จากในแอปที่ติดตั้ง

token อยู่ใน localStorage ของ easygaside.tech สคริปต์บนโดเมนนั้นอ่านได้ จึงทำหน้า `/app` และ `/r` เป็นหน้าเปล่า CSP เข้ม ไม่มี
สคริปต์อื่น และบังคับ PIN ใน Pro ถ้าผู้ใช้เยอะ ควรย้ายไปโดเมนย่อยแยก (`r.easygaside.tech`) ตามผลรีวิวความปลอดภัย

ทางที่ดีกว่าในอนาคต: named tunnel ของ Cloudflare บนโดเมนของเรา (`<รหัส>.remote.<โดเมน>`) ลิงก์ไม่เปลี่ยน ไม่ติดข้อจำกัด
quick tunnel ไม่ต้องส่งต่อคุกกี้ แต่ต้องมีบัญชี Cloudflare + โดเมนที่ DNS อยู่บน Cloudflare

## งานใน UI

- **ตั้งค่า → รีโมท:** สวิตช์, เลือกทาง (นอกบ้าน/Wi-Fi), QR + ลิงก์ + ปุ่มคัดลอก, PIN, รายการอุปกรณ์ + ถอน,
  ลิงก์ Pro (หรือชวนอัปเกรด)
- **แถบล่าง IdeShell (คอม):** ป้าย "รีโมท · 1 เครื่อง" กดไปหน้าตั้งค่า
- **ประวัติแชตโหลดตอนเปิดหน้า:** เดิม `ChatPanel` เริ่มด้วยรายการว่าง เปิดจากมือถือ/รีโหลดแล้วไม่เห็นว่า AI ตอบอะไรไป
  และถ้า AI ยังทำงานอยู่ (จอมือถือดับ stream ขาด) หน้าแชตบอกว่ากำลังทำ แล้วโหลดผลเองเมื่อเสร็จ
- **Electron:** ตอนรีโมทเปิด ปิดหน้าต่างแล้วย่อลง tray (เมนู: เปิดหน้าต่าง / ปิดรีโมท / ออก), `powerSaveBlocker`
  กันเครื่องหลับ, แจ้งเตือนเมื่อมือถือต่อเข้ามาหรือใส่ PIN ผิด (อ่านจาก `remote-state.json` ที่ฝั่ง Next เขียน)

## cloudflared

ดาวน์โหลดตอนเปิดรีโมทนอกบ้านครั้งแรก จาก release ทางการ เวอร์ชันล็อกไว้ ตรวจ SHA256 ที่ฝังในโค้ด
เก็บที่ `<dataRoot>/tools/cloudflared.exe` รันด้วย `childEnv()` เป็นโปรเซสลูกของเซิร์ฟเวอร์ (ปิดแอป = ปิดตาม)
หลุดแล้วเริ่มใหม่เองแบบเว้นระยะ ปิดเองเมื่อไม่มีใครใช้ 2 ชั่วโมง

## ผลรีวิวความปลอดภัย (8 ต.ค.)

ไม่พบระดับ CRITICAL/HIGH แก้แล้ว: open redirect ผ่านตัวอักษรควบคุมใน `next` ของหน้า PIN, ตาราง lockout ที่ถูกล้างได้ด้วยการยิงคีย์ใหม่,
การตรวจ `x-egs-remote` เปลี่ยนเป็นนับว่าเป็นมือถือทันทีที่มี header, `assertLocalRequest` เพิ่มที่เปิดโฟลเดอร์โปรเจกต์ / ใส่คีย์ Pro /
สั่งซื้อ Pro, เตือนว่าโหมด Wi-Fi ไม่เข้ารหัส ที่ยังเหลือ (ยอมรับไว้): คนที่รู้ลิงก์ยิงรหัสจับคู่ผิด 20 ครั้งทำให้รหัสนั้นใช้ไม่ได้
(ต้องกดจับคู่ใหม่), ถอนอุปกรณ์แล้ว stream ที่เปิดค้างอยู่ไม่ถูกตัดทันที, โหมด Wi-Fi เป็น HTTP

## ทดสอบที่ต้องผ่านก่อนออก

- สวิตช์ปิด: พอร์ต gateway ไม่ฟัง, ไม่มี cloudflared
- ไม่มีคุกกี้ / คุกกี้ปลอม / รหัสจับคู่หมดอายุหรือใช้ซ้ำ → หน้า 403 ทุก path รวม `/api/*` และ `/_next/*`
- PIN ผิด 5 ครั้งล็อก, ล็อกแล้วรหัสถูกก็เข้าไม่ได้จนพ้นเวลา
- จากมือถือผ่าน tunnel จริง: สั่ง AI (stream ไหล, ไม่ขาดตอน AI คิดนาน), พรีวิว, เผยแพร่, ประวัติ
- ปิดหน้าต่างคอม → อยู่ใน tray มือถือใช้ได้ · ออกจาก tray → พอร์ตและ cloudflared หายหมด
- server action ที่กันไว้ เรียกจากมือถือได้ 403
- ธีม/ทัวร์บนคอมไม่เพี้ยน (origin ของคอมยังเป็น 127.0.0.1)
