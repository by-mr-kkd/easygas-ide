# ชุดกฎ (rulebook) และสิ่งที่ผู้ใช้เลือกเอง

เอกสารนี้สำหรับคนดูแล EasyGAS IDE: อธิบายว่า AI ได้รับคำสั่งอะไรบ้าง ผู้ใช้เปลี่ยนอะไรได้ และวิธีออกชุดกฎใหม่ให้ทุกเครื่องโดยไม่ต้องออกแอปใหม่

## คำสั่งถึง AI มีสามชั้น

| ชั้น | อยู่ที่ไหน | ใครเปลี่ยนได้ |
|---|---|---|
| 1. กฎที่ห้ามฝ่า | `GAS_RULEBOOK` ใน `lib/gas-codegen.ts` และ lint `validateGasFiles` | คนดูแลแอปเท่านั้น (ต้องออกแอปใหม่) |
| 2. ค่าเริ่มต้นด้านหน้าตา | `DEFAULT_PREFS` ใน `lib/preferences.ts` | คนดูแลแอป |
| 3. สิ่งที่ผู้ใช้เลือก | `settings.json` (ทั้งเครื่อง) และ `project.json` (รายโปรเจกต์) | ผู้ใช้ |

- ชั้น 2 และ 3 ถูกรวมเป็นบล็อกเดียวชื่อ "Look & feel for THIS project" (`renderPrefsBlock`) ก่อนส่งให้ AI ค่าเริ่มต้นจึงไม่เคยถูกเขียนเป็นกฎที่ผู้ใช้ต้องมาหักล้าง
- ชั้น 1 ไม่มีตัวเลือกให้ผู้ใช้ปิด ข้อที่ทำให้แอปพังมี lint จับซ้ำ ข้ออื่นพึ่งคำสั่งใน prompt กับตัวตรวจคุณภาพ จึงไม่ใช่การกันแบบร้อยเปอร์เซ็นต์
- อย่าใส่ชื่อไลบรารีหรือสไตล์ลงใน `GAS_RULEBOOK` อีก ให้เพิ่มเป็นตัวเลือกใน `PREF_FIELDS`

### เพิ่มตัวเลือกสไตล์

เพิ่ม option ใน `PREF_FIELDS` (`lib/preferences.ts`) โดยมี `label`/`hint` ภาษาไทยสำหรับหน้าจอ และ `prompt` ภาษาอังกฤษที่บอก AI ให้ครบว่าใช้อะไร โหลดจากไหน และห้ามใช้อะไรแทน หน้า ตั้งค่า หน้าต่างสไตล์ของโปรเจกต์ wizard และ tool `save_preference` อ่านจากรายการเดียวกันนี้ทั้งหมด

## บทเรียน (lessons)

บทเรียนคือข้อผิดพลาดที่เคยเกิดในเครื่องนี้และโปรเจกต์อื่นอาจเจอซ้ำ เก็บที่ `lessons.json` ในโฟลเดอร์ข้อมูล หนึ่งสมุดต่อเครื่อง แนวคิดมาจากสมุด lessons ของชุด kp-supabase-nextjs

| อะไร | ไปอยู่ที่ไหน |
|---|---|
| ข้อผิดพลาดที่โปรเจกต์อื่นจะเจออีก | บทเรียน |
| การตัดสินใจของโปรเจกต์เดียว หรือความชอบเรื่องหน้าตา | สไตล์ → คำสั่งเพิ่มเติม (ไม่ใช่บทเรียน) |

- **ที่มา:** AI เสนอหลังแก้ข้อผิดพลาดของตัวเอง (tool `propose_lesson` หรือไฟล์ `engine/io/lesson-request.json` ในโหมด Claude Code), แอปนับเองจาก lint (ข้อความเป็นของแอป ตาราง `LINT_LESSONS`) หรือผู้ใช้เขียนเองในหน้า ตั้งค่า
- **ผู้ใช้ต้องกดเก็บก่อนเสมอ:** บทเรียนที่ AI เสนอมีสถานะ "รอตัดสิน" และไม่ถูกส่งเข้า prompt ใด ๆ จนกว่าผู้ใช้กด "เก็บไว้" กับข้อความที่เห็น เหตุผลเดียวกับที่ AI บันทึก "คำสั่งเพิ่มเติม" แทนผู้ใช้ไม่ได้
- **เจอซ้ำให้นับ ไม่เขียนใหม่:** ข้อความซ้ำหรือ `repeatOf` จะเพิ่มตัวนับของข้อเดิม ข้อที่ lint จับได้ครั้งแรกแค่จดไว้ ครั้งที่สองจึงเสนอให้ผู้ใช้
- **การส่งให้ AI** (`pickLessonsForTurn`): สร้างใหม่ได้ทุกข้อที่เก็บไว้ (สูงสุด 12) รอบแก้ไขได้เฉพาะข้อของการ์ดที่เกี่ยวข้อง ข้อทั่วไป และข้อที่เจอตั้งแต่ 2 ครั้ง (สูงสุด 6) บทเรียนไปกับข้อความของรอบนั้น ไม่อยู่ใน system prompt ที่ cache และไม่ถูกเก็บในประวัติแชท
- **ลำดับความสำคัญ:** บทเรียนอยู่ต่ำกว่ากฎชั้น 1 และคำสั่งของผู้ใช้
- **แชร์ขึ้นชุดกฎกลาง:** ปุ่ม "แชร์ให้ชุดกฎกลาง" แสดงข้อความที่จะส่งก่อน (`lessonShareText`: การ์ด, อาการ, กฎ, จำนวนครั้ง, ที่มา) แล้วเปิด GitHub issue ที่กรอกไว้ให้ หรือคัดลอกข้อความ แอปไม่ส่งเอง

ยังไม่ได้ทำ: ทำเครื่องหมายบทเรียนในเครื่องว่า "รวมเข้าชุดกฎแล้ว" เมื่อชุดกฎรุ่นใหม่ครอบคลุมข้อนั้น (ต้องมีทะเบียนฝั่ง repo กฎก่อน) และช่องทางแชร์สำหรับผู้ใช้ที่ไม่มีบัญชี GitHub

## ชุดกฎแบบการ์ด

กฎละเอียดมาจาก <https://github.com/kpcrmv4/gas-best-practices> (MIT) เก็บไว้ใน `rulebook/`:

| ไฟล์ | คืออะไร |
|---|---|
| `rules/*.md` | การ์ดกฎที่คัดลอกมาจากต้นทาง ห้ามแก้มือ ให้แก้ที่ต้นทาง |
| `easygas-map.json` | การ์ดไหนใช้ในแอป อ่านเมื่อไร คำค้น และการ์ดที่ตัดออกพร้อมเหตุผล |
| `source.json` | เวอร์ชันและ commit ของต้นทาง |
| `pack.json` | ไฟล์เดียวที่แอปอ่าน สร้างจากสามอย่างข้างบน ห้ามแก้มือ |

AI ไม่ได้รับกฎทั้งชุด:

- system prompt มีแค่สารบัญ (id และ "อ่านเมื่อไร")
- แอปเลือกการ์ดที่เกี่ยวกับงานจากคำตอบใน wizard สเปคที่ยืนยันแล้ว และข้อความของผู้ใช้ (`routeRules`)
- โหมด API: AI เปิดการ์ดด้วย tool `read_rule` และในรอบสร้างครั้งแรกแอปแนบเนื้อหาการ์ดที่เลือกไปกับข้อความรอบนั้นให้เลย
- โหมด Claude Code: การ์ดถูกเขียนเป็นไฟล์ใน `projects/<id>/engine/rules/` ทุกรอบ แล้ว AI เปิดอ่านเอง

การ์ดสี่ใบถูกตัดออก (`deployment-versioning`, `external-frontend`, `project-structure`, `testing-debugging`) เพราะสอนขั้นตอนที่ผู้ใช้ EasyGAS ไม่ได้ทำเอง และขัดกับกฎชั้น 1

## ออกชุดกฎใหม่

1. แก้และ merge กฎที่ repo ต้นทาง แล้วเพิ่มหัวข้อ `## vX.Y.Z` ใน `CHANGELOG.md` ของต้นทาง เลขเวอร์ชันต้องสูงกว่าเดิม
2. ที่ repo นี้ รัน `npm run rulebook:build -- --source <โฟลเดอร์ต้นทาง>`
   - ถ้าต้นทางมีการ์ดใหม่ สคริปต์จะเตือน ให้เพิ่มการ์ดนั้นใน `rules` หรือ `excluded` ของ `easygas-map.json` แล้วรันอีกครั้ง
3. รัน `npm test` (มี test ตรวจว่า `pack.json` ตรงกับไฟล์ต้นทาง)
4. รัน `npm run rulebook:sign` จะได้ `dist/rulebook/easygas-rulebook.json` และ `easygas-rulebook.json.sig`
5. สร้าง release ใหม่ที่ repo ต้นทาง แล้วแนบสองไฟล์นั้น ชื่อไฟล์ต้องตรงตามนี้
6. commit `rulebook/` ที่นี่ด้วย แอปเวอร์ชันถัดไปจะมีชุดนี้ติดไปตั้งแต่ติดตั้ง

แอปของผู้ใช้จะดึงเองภายในหนึ่งวัน หรือทันทีเมื่อกด "ตรวจหาอัปเดตตอนนี้" ในหน้า ตั้งค่า

ทดสอบก่อนปล่อยจริงได้ด้วยการตั้ง `EASYGAS_RULEBOOK_URL` ให้ชี้ไปที่ไฟล์ทดสอบ (https หรือ `http://127.0.0.1`) การตรวจลายเซ็นยังทำงานเหมือนเดิม

## แอปรับไฟล์อัปเดตเมื่อไร

`verifyAndParsePack` ใน `lib/rulebook/format.ts` เป็นด่านเดียว ตรวจตามลำดับ:

1. ขนาดไม่เกิน 2 MB
2. ลายเซ็น Ed25519 ของไฟล์ทั้งไฟล์ตรงกับกุญแจใน `lib/rulebook/trust.ts`
3. รูปแบบถูก และ hash ของการ์ดแต่ละใบตรง
4. เวอร์ชันสูงกว่าชุดที่ใช้อยู่ (กันการเอา release เก่ามาส่งซ้ำ)
5. `minAppVersion` ไม่สูงกว่าเวอร์ชันแอป

ไม่ผ่านข้อใดข้อหนึ่ง แอปใช้ชุดเดิมต่อ ไฟล์ที่ติดตั้งแล้วถูกตรวจลายเซ็นซ้ำทุกครั้งที่ไฟล์บนดิสก์เปลี่ยน

แอปดาวน์โหลดอย่างเดียว ไม่ส่งข้อมูลหรือโค้ดของผู้ใช้ออกไป ปุ่ม "เสนอกฎใหม่" เปิดหน้า GitHub issue ให้ผู้ใช้เขียนและกดส่งเอง

## กุญแจเซ็นลายเซ็น

- กุญแจลับอยู่ที่ `%USERPROFILE%\.easygas-ide-keys\rulebook-signing-key.pem` นอก repo นี้ ไม่มีรหัสผ่านครอบ
- ใครถือไฟล์นี้ เปลี่ยนคำสั่งที่ AI ในทุกเครื่องทำตามได้ จึงควรสำรองไว้ในที่ปลอดภัย (เช่นตัวจัดการรหัสผ่าน) และไม่เก็บใน repo, cloud drive ที่แชร์ หรือแชท
- ถ้ากุญแจหาย: ออกชุดกฎใหม่ไม่ได้จนกว่าจะออกแอปที่ใส่กุญแจสาธารณะตัวใหม่
- ถ้ากุญแจหลุด: รัน `npm run rulebook:keygen -- --out <ที่ใหม่>` ใส่กุญแจสาธารณะตัวใหม่ใน `RULEBOOK_PUBLIC_KEYS` ลบตัวเก่าออก แล้วออกแอปทันที เครื่องที่ยังไม่อัปเดตแอปจะยังเชื่อกุญแจเก่า
- เปลี่ยนกุญแจตามปกติ: เพิ่มตัวใหม่ไว้คู่กับตัวเก่าหนึ่งรุ่น แล้วค่อยลบตัวเก่าในรุ่นถัดไป
